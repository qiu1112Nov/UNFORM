# UNFORM 3.2.2 — MOTION FIDELITY 修复记录

基于最新已获取的 main `cbb1e69`，开发分支为 `feat/unform-3-2-2-motion-fidelity`。没有直接修改 main，没有公开部署。

## 版本对比与已复现的代码问题

对比 3.1.1 `3c9b0f5`、3.2 `1ff0997` 和 3.2.1 `aa95849`（main 合并为 `cbb1e69`）：

1. **3.2 开始的预响应幅度回退。** 3.1.1 会把约 14% 的预响应目标送入粒子变形弹簧，另外有 2.5% 快速附加通道。3.2 增加 FRAGMENT 后，未确认阶段只保持旧的正式分层目标，几何预响应主要剩 2.5% 通道。手势识别正确但尚未确认时，视觉反馈实际变小。新版本以独立快速通道恢复约 14% 的有界预响应范围，确认后的分层目标保持独立；不是改变 55% 解构强度或 65% 惯性。
2. **单次空结果清空状态。** 3.1.1 与 3.2.1 的 `GestureResponse` 都会在空结果时清空 confirmed/candidate/位置，再次看到手又从 14% 预响应开始。3.2.1 增加完整链路成本节流和 480→256 的输入预算后，低频观测/短时丢帧更容易暴露这个旧问题。输入缩小是否影响某一真机的手部检出率仍需真机记录，不能从模拟数据判定。
3. **确认前的长时间弱反馈。** 两版的 0.68/0.32 开合阈值、80ms 确认目标与 30Hz 上限一致，3.2.1 没有新增更严格的手势阈值。但任何短动作如果只被采到一次，都只能预响应；重新丢帧会再次重启确认。新版本保留两个相符样本与可信关键点校验，允许短暂不确定/缺失样本桥接，确认目标 180ms 有界锁存、仅保留最新反向状态。不会把单个观察擅自升级为完整动作。
4. **低 FPS 时间推进丢失。** 固定 `min(dt, 0.05)` 在 10fps 时每秒只推进约半秒。现在正常前台 dt 可推进至 250ms，分层在同一 dt 内精确跨过 80/160ms 开始边界；长后台间隔仍受保护。弹簧与各层使用同一目标，不追加串联的幅度滤波。
5. **移动与离散状态耦合过紧。** 原位置先有 30ms 低通，渲染中心再有惯性弹簧；单次空检测会一起重置移动历史。TRACE 又固定只认 120ms 内的结果。现在位置/速度从有效采样时间直接取得，离散开合单独保持；移动只经渲染弹簧，TRACE 新鲜度跟随采样间隔，短时保留 160ms 的运动能量，新增有界的手掌移动旋转。

没有找到“随摄像头开启时长持续乘小运动强度”的累计衰减公式。五分钟模拟检查支持端点不衰减，但不能排除真机发热导致推理降频/检出波动，或视觉质量降档带来的稀疏观感。没有把这些尚未测量的因素定为已证实根因。FLOW 修改基准棱线位置、TRACE 仅影响预算内局部轨迹；两者没有覆盖正式解构目标。

旧版反向预响应沿用已有 FRAGMENT 目标，仍会积分弹簧，并非冻结整个分层动画；本次将正式目标显式分离，作为持续推进的不变量测试。不能把这个不变量误报为已找到的旧版冻结错误。

### 历史代码的定量复现

从 Git 历史导出源码，在相同 390×844 模拟 Canvas 环境中，将同一个可信张掌样本送入真实 `ParticleField` 和 `GestureResponse`，推进四帧（66.7ms）。比较可见粒子的平均归一化几何输入 `deformation + previewOffset`，未乘粒子半径/55% 强度；不是模型准确率、屏幕位移或硬件延迟：

| 版本 | 66.7ms 时几何输入均值 | 确认后遇一帧空结果 | 再次识别同样张掌 |
| --- | ---: | --- | --- |
| 3.1.1 | 0.0400 | 状态清空 | 回到 0.14 预响应 |
| 3.2.1 | 0.0196 | 状态清空 | 回到 0.14 预响应 |
| 3.2.2 | 0.1097 | 保持完整目标 1 | 目标仍为 1 |

新预响应通道比旧的主惯性通道更快，不能把表格解释成“与 3.1.1 完全相同的艺术时序”。需要真机确认其强度是否合适。正式解构目标仍为归一化 0/1，空间强度仍乘 0.55；反向动作可立即预反馈，正式反向目标最多受 180ms 短锁存和下一有效采样约束。快速反向时惯性仍会限制实际端点到达，未承诺每个极短动作都瞬间到达完整位移。

## 平板兼容路径

- 取帧前检查 readyState≥2、videoWidth/videoHeight>0、有效新视频时间；尺寸延迟就绪不会向模型送入 1×1/无效图像。
- 输入使用实际解码视频的原始方向和宽高比。横竖屏变化重新计算输入尺寸，不根据 viewport 或 User-Agent 强制旋转/裁剪。前置摄像头只在预览及输出坐标镜像一次；如果实际 track 报告 environment，预览与输出都取消镜像；未知 facingMode 会明确显示 unknown。
- Worker 初始化失败、运行错误、帧处理/Bitmap 超时（各约 2 秒）会终止失败 Worker，再加载原主线程模型。过期 session 的结果不再派发，取消期间迟到的模型/Bitmap 会释放。初始化请求有 20 秒超时，避免永远停在加载中。
- 同时只有一次在途推理，回退期间也不会叠加两个模型。回退保持成本自适应与 1.5 倍空闲余量，Worker 保持原 30Hz 上限及成本调度，不通过恢复高频阻塞识别求灵敏度。
- rVFC 不交付新帧超过约 1.5 秒时切换 RAF 查询真实视频时间；不会制造重复帧。持续空结果只显示 running / no hand，不据此循环重启后端或伪造手势。
- 诊断分别显示 camera/model/inference，实际 backend、尺寸、readyState、视频时间、facingMode、推理频率、最后成功识别时间及错误原因。模型就绪并不等于检测成功；无推理进展显示 stalled/等待有效尺寸。

- Headless Chromium 浏览器回归通过：触控编织/撕裂、单一渲染循环、摄像头重启、平板模拟视口与延迟视频尺寸、Worker 初始化及运行错误回退、桌面质量、诊断面板；没有捕获到页面错误或失败 HTTP 响应。生产 `/UNFORM/` 下 Worker、MediaPipe bundle 和 WASM 返回 200，真实模型在 Worker 中完成初始化与伪视频推理。模型请求使用上一轮经正常 TLS 下载并核对官方 ETag 的本地测试工件注入，未关闭 TLS 校验，应用模型 URL 未改。伪视频没有真人手；手势输出与快速响应部分使用合成关键点，因此不构成真机识别或物理动作延迟验证。
- 未改动 3.2.1 的推理尺寸档位、视觉自适应配置、手机初始 595 粒子、4 个 TRACE 历史采样、DPR 上限 1.5、桌面预算及 GitHub Pages `/UNFORM/` 配置；没有新增依赖。

仍需安卓手机和平板真机验证：不同光线/手距下的快速张掌握拳检出率，完全落在两次推理之间的动作漏采，预响应与锁存观感，低分辨率下的关键点质量，持续使用发热/功耗/帧率，真实横竖屏相机方向、实际前后摄选择，以及各平板浏览器的 Worker/Bitmap/WASM 和主线程回退性能。主线程回退能提供兼容路径，但无法保证每台低性能设备流畅，也不能通过模型加载成功证明手部识别成功。
