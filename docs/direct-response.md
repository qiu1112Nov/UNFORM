# UNFORM 3.2.3 — DIRECT RESPONSE

基线为最新取得的 main `c80f5fa`（合并 3.2.2 `2e99131`），独立分支 `feat/unform-3-2-3-direct-response`。

## 实际根因与复现

3.2.2 的 `ParticleField.projectAll` 将 `p.deformation.value + quickFeedback.value * 0.14` 合成几何进度。这是两组不同速度的运动状态：正式 `FragmentLayers.states` 使用 65% 惯性与 80/160ms 分层延迟，预响应 `quickFeedback` 使用 4 倍速弹簧。`GestureResponse` 正式确认时把 feedback 置零，快速通道开始消退；内层正式动画尚未开始，于是粒子先回去，再开始正式解构。握拳时同样存在负附加位移消退造成的反向回摆。即使没有 unknown/no-hand，也可复现。

此外，180ms 目标锁存可能在反向姿态已确认后继续输出旧正式目标，而几何预响应已经结束。它不是此次单向张掌复现的必要条件，但会进一步干扰反向交接。

从 Git 导出原版源码，与新代码使用相同输入：只张掌、不移动手掌，120fps 更新，100ms 确认；记录归一化内层几何进度（不是摄像头准确率或物理动作延迟）：

| 时间 | 3.2.2 合成进度 | 3.2.3 单一弹簧进度 |
| --- | ---: | ---: |
| 50ms | 0.0854 | 0.0854 |
| 100ms | 0.1291 | 0.1346 |
| 150ms | 0.0428 | 0.1400 |
| 200ms | 0.0033 | 0.1400 |
| 250ms | 0.0000 | 0.1400 |
| 300ms | 0.0761 | 0.2059 |
| 400ms | 0.4346 | 0.5138 |

同一段 400ms 采样中，原版最大单帧回退约 0.0165，新版为 0。将新增的实际粒子投影测试放回原版源码后，张掌与握拳两项均失败：200ms 时分别出现约 0.1220→0.1127、0.1315→0.1216 的目标方向归一化位移回退；新版两项通过。这些测试固定 idle/FLOW 时间与手掌位置，以排除自转、棱线流动及镜头投影变化造成的干扰。

未发现需要通过重启模型或提升推理频率解决的证据。Worker 保持串行和 session 校验，新增测试确认迟到的旧 Worker 结果不会覆盖新摄像头会话的手势。

## 修复方式

- **一组几何状态：**预响应直接推进 `FragmentLayers.states`，每层目标最多从当前位置向可信方向移动约 0.14。后续重复帧不会把预响应目标继续累加。
- **连续交接：**正式确认只改目标和分层调度，不复制、归零或重建 state；对象、value、velocity 均保留。等待的层继续接近/停在自己的预响应目标，避免重新朝旧 home 运动。确认后的正常 65% 弹簧仍保留。
- **无附加几何消退：**从 `projectAll` 中移除 quickFeedback 的几何加项；它仅影响微弱亮度提示。整体 activation 在正八面体下由实际三层进度派生，避免另一套弹簧驱动线条与粒子竞争。
- **不延迟控制：**移除额外 180ms 目标锁存；约 80ms、两个一致样本的确认规则不变。已确认目标继续保持，只有明确的可信反向才更新意图；短暂不确定/丢帧不会把预响应置零。持续失去追踪、关闭摄像头或复位仍会释放控制。
- **稳定手机提示：**使用与控制共用输出中的 confirmedPose 显示文案，不再以另一个原始 openness>0.55 阈值逐帧切换。固定提示区高度，不重复写入相同文字。没有 UI 防抖定时器，也没有把显示稳定策略放到控制路径上。
- **保留性能：**没有改变摄像头采样/推理频率、Worker/回退实现、输入尺寸预算、手机粒子/TRACE/DPR 配置、依赖、55%/65% 参数或 Pages 配置。新增状态复用固定的三个层对象及目标数组，无额外渲染循环。

## 验证结果

- `npm test`：全部 12 个测试文件通过；`node --test --test-isolation=none tests/*.test.js`：**90 项用例通过**。
- `npm run build`、`git diff --check`：通过。
- 新增覆盖张掌/握拳在 10/20/30/60/120fps 的连续方向进度，短暂 unknown/no-hand、不重置位置与速度、真实粒子投影、亮度通道不再改变坐标、确认后无锁存等待、旧 Worker 结果丢弃，以及提示文案与控制输出独立。方向测试采用 0.001 归一化容差，允许保留的弹性系统末端极微小收敛，禁止预响应交接的大幅回撤。
- Headless Chromium 回归通过：合成手势即时预响应、提示原始阈值抖动时文案不切换、张掌/握拳时摄像头提示窗口高度一致、单渲染循环、手机触控、桌面质量、平板模拟视口与延迟就绪、Worker 初始化/运行回退及诊断。
- 生产 `/UNFORM/` Worker、MediaPipe bundle 和 WASM 资源加载正常；真实模型在 Worker 中完成初始化与伪视频推理，没有捕获到页面错误或失败 HTTP 响应。模型请求沿用经正常 TLS 下载并核对官方 ETag 的测试工件注入，未关闭 TLS 校验，应用的模型 URL 没有修改。

这些结果不等于安卓真机问题已彻底解决。仍需手机和平板验证实际交接观感、快速反向时惯性表现、不同推理频率与光线下的识别、长期发热/帧率，以及提示窗口横竖屏布局。完全落在两次采样之间的手势仍可能未被观察，不能凭空恢复。没有合并 main 或公开发布。
